## 目的と今回の範囲

iPhoneのショートカットでPCに表示されたQRコードを読み取り、送信先URLを取得する。そのショートカット内で現在地を取得し、Cloudflare Tunnel経由でPCへ送信してターミナルに表示する。

実装担当範囲はPC内の処理のみとする。スマホ側のショートカット作成・設定・操作は利用者が担当し、専用の手順書は作成しない。

スマホではWebページを開かない。今回は位置情報の取得・送信・表示までを対象とし、SQLiteへの保存、Speedtestとの統合、位置の継続追跡、場所名や階数の入力は対象外とする。位置情報だけの受信を、完了したネットワーク測定として扱わない。

README.mdは明示的な編集指示があるまで編集しない。方針確定と完成後に整理するという利用者の意向に従う。

## 現在の構成

- `scripts/phone_location_probe.py`：127.0.0.1:8765で待ち受け、POST /locationで受け取ったJSONをターミナルに表示する。GET /locationは疎通確認用。
- `scripts/cloudflare_tunnel.py`：cloudflaredを起動し、ログから一時的なHTTPS URLを取得して表示する。
- `src/location.py`：Windows本体から位置情報を取得する既存処理。
- ターミナルのQRコード生成は実装済み。ショートカットの設定は利用者が担当する。
- 受信処理は文字列またはJSON数値の座標をfloatに変換し、有限性と範囲を検証する。スマホ受信機能から精度フィールドは削除済み。

## 操作の流れ

1. PCのターミナルで受信スクリプトを起動する。
2. 別のターミナルでCloudflare起動スクリプトを実行する。
3. 起動スクリプトが取得した公開URLに /location を付け、送信先URLとQRコードを表示する。
4. iPhoneであらかじめ作成したショートカットを実行する。
5. ショートカットの「QRコードまたはバーコードをスキャン」相当のアクションでPCのQRコードを読む。
6. 読み取ったURLを検証し、「現在地を取得」から緯度・経度を取り出す。
7. 「URLの内容を取得」のPOST・JSON設定で位置情報を送信する。
8. PCが検証済みの位置情報を表示し、ショートカットが応答を確認して完了を表示する。

通常のカメラアプリからURLを開く操作ではなく、ショートカット内でスキャンする。トンネル再起動でURLが変わっても、QRコードを読み直すだけで送信先を更新できる。初回や公開ホスト変更時には、カメラ、位置情報、通信先へのアクセス許可が必要になる場合がある。

| 用途 | 技術・方針 |

| 受信 | Python標準ライブラリのhttp.serverを継続使用 |

qrcodeは既に承認・導入済み。今回のサニタイズにはfloat、math.isfinite、datetimeなどPython標準の機能を使用し、新規依存関係は追加しない。QRコードはターミナル出力のみとし、外部のQR生成サービスにはURLを渡さない。

## 実装内容

### PC側

- 既存の2ターミナル構成を維持する。
- Cloudflareから得た送信先URLをQRコードとしてターミナルに表示する。
- 初回実装では画像ファイルを生成しない。ターミナルのQRコードを読み取れない場合に限り、SVG出力を後続の代替案として検討する。
- 既存の受信サイズ上限・タイムアウトを維持し、緯度・経度をサニタイズしてから値を検証する。
- このスマホ受信機能から精度フィールドを完全に削除する。受信仕様、変換・検証、表示、起動メッセージ、関連テストに含めない。既存のWindows位置取得機能は変更しない。
- 成功時はJSON応答を返し、位置情報を整形して即時にターミナルへ出力する。
- GET /locationの疎通確認機能は維持する。
- cloudflared未導入、URL取得失敗、ポート使用中を分かる形で表示する。Ctrl+Cで終了し、トンネル起動側は子プロセスを停止する。

### スマホ側との接続仕様

スマホ側は利用者が担当する。PC側は、QRコードに含めた送信先URLへのJSON POSTを受信し、成功時にstatusがokのJSONを返す。送信データの形式は次項のとおりとする。

### データ形式

| フィールド | 必須 | 内容 |
| --- | --- | --- |
| latitude | はい | 緯度の文字列。Python側でfloatに変換後、-90から90の有限数値として検証 |
| longitude | はい | 経度の文字列。Python側でfloatに変換後、-180から180の有限数値として検証 |
| sent_at | はい | ショートカットで送信前に生成したタイムゾーン付きISO 8601日時。PC側でUTCに変換 |
| received_at | PC側で付与 | PCで受信したUTC日時 |

`accuracy_meters`はこの機能の仕様から削除する。送信不要であり、返却・表示するデータにも含めない。

### サニタイズと検証の順序

1. JSONを解析し、トップレベルがオブジェクトであることと必須フィールドの存在を確認する。
2. latitude・longitudeは文字列を基本入力とし、従来のJSON数値も受け付ける。真偽値・null・配列・オブジェクトは変換前に拒否する。
3. 文字列は前後の空白を除去し、各値についてfloatへの変換を試す。空文字、数値以外の文字、変換時のValueError・TypeError・OverflowErrorは、そのフィールドの変換エラーとして直ちに返す。
4. 変換後にmath.isfiniteで有限性を確認する。floatへの変換が成功しても、NaN・Infinity・桁あふれで無限大になった値は拒否する。
5. 有限性確認後、latitudeは-90から90、longitudeは-180から180の範囲内か検証する。範囲外は値の検証エラーとして返す。
6. sent_atは文字列としてISO 8601の日時に解析し、タイムゾーンの存在を確認する。Z・+00:00に加え、-05:00などの時差付き日時も受け付け、astimezone(timezone.utc)でUTCへ変換する。タイムゾーンなし、不正な日時、UTC変換で対応範囲を超える日時は拒否する。
7. すべての検証成功後、緯度・経度はfloat、日時はUTCのISO 8601文字列に統一し、PC側でreceived_atを付与して表示する。

度記号、方位記号、カンマを含む表記から数字だけを抜き出すような補正はしない。例えば `"40.42"` は受け付け、`"40.42°N"` や `"40,42"` は変換エラーとする。不足値を0などに置き換えない。定義したフィールドだけを出力する。

エラーはHTTP 400とし、JSON解析・型変換・値検証の段階と対象フィールド、理由が分かるレスポンスを返す。最初の失敗時点で処理を終了し、不正な受信データを成功として表示しない。

レスポンスのstageはJSON解析が `json_decode`、座標の型変換が `conversion`、必須項目・値・日時の検証が `validation`。フィールド単位のエラーはfieldに対象名を含め、errorに理由を返す。JSON全体の構文不正など、対象フィールドを特定できない場合はfieldを省略する。

### 公開URLへの最小限のアクセス制御

受信サーバー起動時にランダムトークンを生成し、同じ値をCloudflare起動スクリプトの引数で渡す。QRコードにはトークン付きの送信先URLを含め、受信時に照合する。受信サーバーの起動メッセージに、トークンを渡すための起動コマンドを表示する。

トークンなし・不一致のPOSTは拒否する。HTTPアクセスログにはトークン付きURLを出力しない。トークンやQRコードを永続的な認証情報として扱わず、起動ごとに更新する。QRコードを共有した相手も送信できるため、使用中だけ受信サーバーとトンネルを起動する。

### PC側の起動方法

プロジェクトのルートで次を実行する。

```powershell
.\.venv\Scripts\python.exe scripts\phone_location_probe.py
```

起動後に表示される `cloudflare_tunnel.py --token ...` のコマンドを別ターミナルで実行する。QRコードには `/location?token=...` まで含まれる。そのURL全体を送信先とし、Content-Typeをapplication/jsonにして以下のJSONをPOSTする。

```json
{
  "latitude": "40.42",
  "longitude": "-86.91",
  "sent_at": "2026-11-04T12:00:00Z"
}
```

sent_atは実際の送信準備時刻に置き換える。例えば2026-11-04T07:00:00-05:00は、PC側で2026-11-04T12:00:00Zとして表示する。成功応答は `{"status": "ok"}`。受信データはPCのターミナルに表示し、ファイルやDBには保存しない。終了時は両方のターミナルでそれぞれCtrl+Cを押す。
